# 서울시 상권 쇠퇴 조기경보 대시보드

> 상권이 무너지기 전, 신호를 먼저 잡는다

제2회 BDAI × 플랜잇 데이터 분석 공모전(주제: 도시의 신호를 읽다, 개인전) 출품작입니다. 상권 쇠퇴 진단 영역을 선택해 예선(분석 기획안)부터 본선(Tableau 대시보드 구현, AI 활용, 정책 제언)까지 진행한 전 과정을 담았습니다.

## 프로젝트 요약

- **문제의식**: 기존 상권 분석은 대부분 쇠퇴가 확정된 뒤의 사후 진단입니다. 이 프로젝트는 폐업이 본격화되기 전 초기 신호(순증감율 마이너스 + 폐업률 가속화)를 잡아 정책 개입 시점을 앞당기는 조기경보 도구를 목표로 합니다.
- **데이터**: 서울시 상권분석서비스 2025년 1~4분기, 25개 자치구 · 1,650개 상권 (점포/업종, 상권 위치, 주변 집객시설 3종)
- **산출물**: Tableau 대시보드 2개 화면, AI 진단 리포트(위험도 상위 50개 상권), Tableau MCP 자연어 질의, KPI별 정책 제언

## 핵심 결과

- **위험 상권 285개**(전체 1,650개 중 17.3%)를 판정했습니다.
- **자치구별 격차**: 위험 상권 비율은 동작구 26.3%(15/57), 강동구 25.0%(15/60), 양천구 23.2%(13/56) 순으로 높고, 금천구·중구·용산구가 낮습니다. 상·하위 격차는 2배 이상입니다.
- **예상과 반대였던 발견**: 골목상권·전통시장이 더 취약할 것이라는 예상과 달리 **발달상권의 위험 비율이 22.9%(57/249)로 가장 높았습니다**(골목상권 16.4%, 전통시장 15.7%). 발달상권의 평균 순증감율은 4개 분기 동안 -1.2% → -2.6% → -2.0% → -3.2%로 지속 하락했습니다.
- **원인 가설 검증**: 변동성이 커서 위험 기준에 걸린 것도(표준편차 발달상권 0.056 < 골목상권·전통시장 0.089), 프랜차이즈 침투(위험군 1.90% vs 비위험군 1.99%)도 아니었습니다. 근본 원인(임대료, 유동인구 등)은 보유 데이터로 규명하지 못했습니다.
- **통과형 상권 가설**: 위험 상권에는 지하철역·버스정거장·은행·약국 같은 인프라가 오히려 더 많았고, 유동인구는 있으나 소비로 이어지지 않는 상권일 가능성을 가설로 세웠습니다(검증 미완).
- **정책 제언**: KPI별 선제 개입 방안 3가지와 함께, 발달상권을 위험 임계값 미달이어도 전수 모니터링 대상으로 지정하는 안을 제안했습니다.

> 표준편차와 프랜차이즈 침투율 수치는 `02_EDA_상권쇠퇴분석.ipynb` STEP 5·6 기준이며, 최소 표본 필터를 적용하기 전의 위험 판정 집합으로 계산한 값입니다.

## 분석 방법

### KPI와 위험 판정

| KPI | 산식 |
|---|---|
| KPI-1 순증감율 | (개업 − 폐업) / 전체 점포 수 |
| KPI-2 폐업률 증감 | 이번 분기 폐업률 − 전분기 폐업률 |
| KPI-3 프랜차이즈 침투율 | 프랜차이즈 점포 수 / 전체 점포 수 |

- **위험 판정**: 순증감율 < 0 **그리고** 폐업률 증감 > 0 (최신 분기 20254 기준). 점포가 줄고 있을 뿐 아니라 그 감소가 가속화되는 상권만 위험군으로 봅니다.
- **최소 표본**: 전체 점포 수 30개 미만 상권은 비율이 쉽게 흔들리므로 판정에서 제외했습니다(299개 → 285개).
- KPI는 100개 서비스 업종을 먼저 상권×분기로 합산한 뒤 비율을 계산합니다.

### 데이터 점검과 전처리

원본 점포 데이터에서 다음 오류를 확인해 처리했습니다. 점검과 보정 과정은 [`02_EDA_상권쇠퇴분석.ipynb`](notebooks/02_EDA_상권쇠퇴분석.ipynb) STEP 1에 있습니다.

- **프랜차이즈 점포 수**: 값이 전체 점포 수보다 큰 행이 약 4.8%(14,705건) 있었습니다. 개수가 아니라 비율(%)이 입력된 원본 오류로 판단해 개수로 환산해 복원했습니다.
- **전체 점포 수**: 일부 행이 실제보다 작게 기록되어, 일반·프랜차이즈 보정값의 합과 비교해 큰 값을 사용했습니다.
- **개업 점포 수**: 비슷한 오류가 의심됐지만 같은 보정을 적용하면 위험 상권 판정이 299개에서 439개로 크게 흔들려, 확신이 부족하다고 판단했습니다. 전체 점포 수를 초과하는 값만 상한선으로 눌러주는 보수적 방식을 택했습니다([검증 노트북](notebooks/05_개업점포수_보정_검증.ipynb)).
- **결측치**: 주변 시설 데이터의 빈 값은 해당 시설이 없는 것으로 보고 0으로 채웠습니다. 점포·상권 위치 데이터에는 결측이 없었습니다.

## 대시보드 (Tableau)

[`deliverables/DashBoard.twbx`](deliverables/DashBoard.twbx)

- **화면 1 — 자치구 단위 현황 진단**: KPI 카드 4개, 자치구별 위험 비율 막대그래프와 Choropleth 지도, 분기별 순증감율 추이 라인차트, 상권 구분별 비교
- **화면 2 — 상권 단위 원인 분석**: 위험 상권에 많은/적은 업종 Top10, 위험 상권에 많은/적은 시설 Top10, 위험 상권 통합 테이블(285개), 상권 상세 지도, AI 진단 리포트

자치구 → 상권으로 내려가는 드릴다운 구조이며, 통합 테이블에서 상권을 선택하면 해당 상권의 AI 진단 리포트가 필터 액션으로 표시됩니다.

## AI 활용

1. **AI 진단 리포트**: 위험도(순증감율) 상위 50개 상권에 대해 진단 요약 → 원인 가설 → 정책 제안 3단 리포트를 생성했습니다. 각 단계의 근거를 제한해(진단은 KPI 수치만, 원인은 업종·시설 데이터만, 정책은 KPI-정책 매칭표만) 근거 없는 내용이 섞이지 않도록 했습니다. 원래는 Claude API로 285개 전체를 만들 계획이었으나 API 키가 없어 Claude Code 세션이 직접 작성했고, 그 때문에 범위를 상위 50개로 줄였습니다. 생성한 리포트는 대시보드 화면 2에서 확인할 수 있습니다.
2. **Tableau MCP**: Claude Desktop에 Tableau 공식 MCP 커넥터를 연결해 게시된 데이터소스에 자연어로 질의했습니다. 위험 상권 수(285개)와 위험 비율 상위 5개 자치구 응답이 대시보드 값과 일치함을 확인했습니다.
3. **개발 과정 전반**: 데이터 정합성 검증과 Tableau 관계(Relationship) 연결 시 발생한 fan-out 문제 진단·해결, UI 개선에 Claude Code를 활용했고, 모든 수치는 Python 재계산과 대조했습니다.

## 재현 방법

1. [`data/README.md`](data/README.md)를 보고 원본 CSV 3개를 `data/`에 넣습니다.
2. 의존성을 설치합니다: `pip install pandas numpy pyproj jupyter`
3. `notebooks/`의 노트북을 `01`부터 `06`까지 순서대로 실행합니다. 노트북은 `notebooks/` 폴더를 기준으로 `../data`, `../data_clean` 상대경로를 사용합니다. 06이 `data_clean/`에 정제 CSV 4종을 만듭니다.
4. 대시보드는 Tableau Desktop에서 `.twbx`를 열면 됩니다. 파일에 Tableau 추출(Extract)이 내장되어 있어 CSV 없이도 열립니다.

Python 3.9(pandas 2.3, pyproj 3.6)에서 노트북 01~06을 순서대로 실행해, 06이 만든 정제 CSV 4종이 작업 환경에서 만든 파일과 동일하게 재생성되는 것을 확인했습니다.
